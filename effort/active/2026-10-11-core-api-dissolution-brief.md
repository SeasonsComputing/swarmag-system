# Core API Dissolution — Brief

**Active, production scope approved.** Recorded 2026-10-11 from a CA + AI Architect session. A Foundation
change to `core/`: the `core/api/` namespace is removed and its two contracts move into
`core/std/`, exported through `@core/stdx`. AI Coding Engine review and CA scope authorization are
complete.

## What triggered it

Designing list queries centered on `core/api/api-contract.ts`. The CA observed that `core/api/` is a
namespace holding nothing but contracts.

## What the repository holds

- **`core/api/api-contract.ts`:** the CRUD, list, and business-rule contracts
  (`CrudBaseContract`, `AdaptedUpdateContract`, `DirectUpdateContract`, `CrudListContract`,
  `ApiCrudContract`, `ApiBusRuleContract`), their result and option types (`DeleteResult`,
  `ListOptions`, `ListResult`), the list constants and helpers, and the error machinery
  (`ApiError`, `ApiErrorDetail`, `checkApiError`, `throwApiError`, `apiError`,
  `checkValidatorError`).
- **`core/api/api-auth-contract.ts`:** `ApiAuthContract` and `Session`.
- **Implementers and consumers.** `core/cli` implements both: the client makers implement the CRUD
  and business-rule contracts, and `AuthSupabaseClient` implements `ApiAuthContract`. Consumers sit
  in `back/`, `front/`, `ux/`, and `tests/`.
- **References:** 13 contract-importing source files plus one guard reference under `source/` (`back` 2,
  `core/cli` 5, `devops` 1, `front` 2,
  `tests` 2, `ux` 2), plus generated copies under `supabase/functions/_shared/`.
- **`@core/stdx`** exports `make-adapter.ts`, `make-scope.ts`, and `wrap-http-handler.ts`.
- **`guard-architecture.ts`** lists `'@core/api/'` in `UX_FORBIDDEN_IMPORTS`, which applies to app
  files (`isUxAppFile`). Its message directs apps to `@front/api/api.ts`, `@domain`, or the obsolete
  literal alias `@core-std`.

## Decisions (CA, 2026-10-11)

1. **`core/api/` is removed.** `core` keeps `cfg`, `cli`, `db`, `std`, and `svc`.
2. **`api-contract.ts` becomes `core/std/api-contracts.ts`** (plural), exported through `@core/stdx`.
3. **`api-auth-contract.ts` becomes `core/std/auth-contract.ts`,** exported through `@core/stdx`.
4. **Contracts live where implementer and consumer both see them.** `core/cli` implements both
   contracts and may not import `ux` or `front` (`architecture-core.md` §7); `core/std` is visible
   to every layer. Placing the auth contract in `ux/shell/runtime/`, beside its consumer
   `logout.ts`, was proposed first and rejected: it would force `AuthSupabaseClient` out of the
   `core` library.
5. **`@core/stdx`, not `@core/std`.** The contracts carry runtime parts (`ApiError`, the checking
   helpers, the list helpers); exporting them through `stdx` keeps the `std` primitives barrel lean
   and lets a tree shaker drop what a bundle never uses.
6. **The guard's `'@core/api/'` entry is removed, not replaced.** It first appears in `ec67411`
   (2026-02-16), a commit described as a rename that rewrote the guard with no recorded rationale;
   the `@domain/adapters/` entry from the same list was removed on 2026-08-31 for the same reason.
   When it appeared, `core/api/` held the client implementations, which moved to `core/client/` on
   2026-04-02 (`90d6d1e`), subsequently renamed to `core/cli/` (`189a505`), leaving the rule blocking
   only contracts. No rule takes its place:
   Application features continue consuming the composed API through `@front/api/api.ts`. Application
   code may reach the contracts through `@core/stdx`, as `architecture-core.md` §5.2.4 already
   shows with `apiError(error)`.
7. **A guard keeps `core/std` closed: it imports only relative files.** A file under
   `source/core/std/` may import nothing but relative paths within `std`; no other `core`
   namespace, no higher layer, and no third-party library. Nothing enforces this today:
   `guard-architecture.ts` checks top-level namespaces only, so `core/std` importing `@core/cli`
   would pass. Every current `std` import is already relative, and the two moved contracts import
   only `@core/std` and `@core/stdx`, which become relative imports of individual modules once inside.
   Static/type imports, re-exports, side-effect imports, and literal dynamic imports are checked;
   relative targets must resolve within `source/core/std/`. The invariant lives in Architecture Core
   §10.1 beside “Domain is pure”; §10.2 identifies guards as the enforcement layer.

## Review corrections (CA, 2026-10-11)

Raised in the CA and AI Architect review of the production report. Three concern the guard; each
follows from the guard's history in this repository, where entries added without a stated rule or a
recorded reason (`'@core/api/'`, `'@domain/adapters/'`) outlived their purpose unnoticed.

1. **`tests` may import `devops`; the file-pair exception is removed.** The production let
   `architecture-guard-test.ts` alone import `guard-architecture.ts`, a hardcoded carve-out inside
   the guard's logic. In its place, `tests` may import `devops`, stated in `architecture-core.md`
   §7 and in `AllowedDeps`. `tests` already imports every other layer; tests verify behavior,
   tooling included. The direction is one-way: `devops` runs tests through tasks and never imports
   them, so there is no cycle. The exception paragraph in `architecture-core.md` is removed.
2. **The import scanner rewrite is accepted and recorded.** `findImports` serves every architecture
   rule, not only the `std` rule. It now skips comments and string literals and recognizes default
   and side-effect imports. Compared across all 231 source files, the new scanner finds every
   import the old one found except one false positive (a template literal in the new test file), and
   39 the old one never saw: every side-effect import, among them the CSS barrel's stylesheets, the
   panel stylesheets, and `@tests/config/test-config.ts`. It is strictly stricter; `deno task check`
   passes.
3. **The invariant is numbered §10.1.11.** "Core standard library is closed" moves from an
   unnumbered heading between §10.1.1 and §10.1.2 to §10.1.11, last in the list, so every existing
   number holds (the roadmap cites §10.1.5). Its bullets wrap within 105 characters.
