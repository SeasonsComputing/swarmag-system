# Core API Dissolution — Brief

**Active, not yet dispatched.** Recorded 2026-10-11 from a CA + AI Architect session. A Foundation
change to `core/`: the `core/api/` namespace is removed and its two contracts move into
`core/std/`, exported through `@core/stdx`. It awaits AI Coding Engine review and the production
gate. A candidate to ride with `effort/active/2026-10-11-list-query-brief.md`, which rewrites the
same contract file.

## What triggered it

Designing list queries centered on `core/api/api-contract.ts`. The CA observed that `core/api/` is a
namespace holding nothing but contracts.

## What the repository holds

- **`core/api/api-contract.ts`:** the CRUD, list, and business-rule contracts
  (`CrudBaseContract`, `AdaptedUpdateContract`, `DirectUpdateContract`, `CrudListContract`,
  `ApiCrudContract`, `ApiBusRuleContract`), their result and option types (`DeleteResult`,
  `ListOptions`, `ListResult`), the list constants and helpers, and the error machinery
  (`ApiError`, `ApiErrorDetail`, `checkApiError`, `throwApiError`, `apiError`,
  `checkValidatorError`).
- **`core/api/api-auth-contract.ts`:** `ApiAuthContract` and `Session`.
- **Implementers and consumers.** `core/cli` implements both: the client makers implement the CRUD
  and business-rule contracts, and `AuthSupabaseClient` implements `ApiAuthContract`. Consumers sit
  in `back/`, `front/`, `ux/`, and `tests/`.
- **Importers:** 14 source files under `source/` (`back` 2, `core/cli` 5, `devops` 1, `front` 2,
  `tests` 2, `ux` 2), plus generated copies under `supabase/functions/_shared/`.
- **`@core/stdx`** exports `make-adapter.ts`, `make-scope.ts`, and `wrap-http-handler.ts`.
- **`guard-architecture.ts`** lists `'@core/api/'` in `UX_FORBIDDEN_IMPORTS`, which applies to app
  files (`isUxAppFile`). Its message directs apps to `@front/api/api.ts`, `@domain`, or `@core/std`.

## Decisions (CA, 2026-10-11)

1. **`core/api/` is removed.** `core` keeps `cfg`, `cli`, `db`, `std`, and `svc`.
2. **`api-contract.ts` becomes `core/std/api-contracts.ts`** (plural), exported through `@core/stdx`.
3. **`api-auth-contract.ts` becomes `core/std/auth-contract.ts`,** exported through `@core/stdx`.
4. **Contracts live where implementer and consumer both see them.** `core/cli` implements both
   contracts and may not import `ux` or `front` (`architecture-core.md` §7); `core/std` is visible
   to every layer. Placing the auth contract in `ux/shell/runtime/`, beside its consumer
   `logout.ts`, was proposed first and rejected: it would force `AuthSupabaseClient` out of the
   `core` library.
5. **`@core/stdx`, not `@core/std`.** The contracts carry runtime parts (`ApiError`, the checking
   helpers, the list helpers); exporting them through `stdx` keeps the `std` primitives barrel lean
   and lets a tree shaker drop what a bundle never uses.
6. **The guard's `'@core/api/'` entry is removed, not replaced.** It first appears in `ec67411`
   (2026-02-16), a commit described as a rename that rewrote the guard with no recorded rationale;
   the `@domain/adapters/` entry from the same list was removed on 2026-08-31 for the same reason.
   When it appeared, `core/api/` held the client implementations, which moved to `core/cli/` on
   2026-04-02 (`90d6d1e`), leaving the rule blocking only contracts. No rule takes its place:
   `core/cli` is the client namespace, and client applications using it is its purpose. Application
   code may reach the contracts through `@core/stdx`, as `architecture-core.md` §5.2.4 already
   shows with `apiError(error)`.
7. **A guard keeps `core/std` closed: it imports only relative files.** A file under
   `source/core/std/` may import nothing but relative paths within `std`; no other `core`
   namespace, no higher layer, and no third-party library. Nothing enforces this today:
   `guard-architecture.ts` checks top-level namespaces only, so `core/std` importing `@core/cli`
   would pass. Every current `std` import is already relative, and the two moved contracts import
   only `@core/std` and `@core/stdx`, which become relative once inside.

## Scope the production will touch

- `core/api/` removed; `core/std/api-contracts.ts` and `core/std/auth-contract.ts` added;
  `core/std/stdx.ts` exports both.
- Every importer rewritten to `@core/stdx`. `supabase/functions/_shared/` is regenerated by
  `deno task edge-sync`, never edited by hand.
- `guard-architecture.ts`: the `'@core/api/'` entry is removed with the namespace (decision 6),
  and the `core/std` relative-only rule is added (decision 7).
- `architecture-core.md` §5.2 and §8, and `architecture-front.md` §8.1.1, §9.3, and §9.5.1, where
  they cite `core/api` paths.
- File headers of the moved files follow `CONVENTIONS.md` §6.2.
